## specjutsu

This project uses specjutsu: every behaviour is a scenario with an ID in the spec folder,
every scenario has a test, and each test must fail before its code is written.

- Start with `sj status`, then `sj next` for the task's scenarios, files and test commands.
  Don't read whole spec folders or raw test logs.
- Write the failing test first and run `sj test <ID>`. Edits to source files are blocked
  until the task's scenarios have a red run.
- Close tasks with `sj task done <change> <task>`, never by editing the checkbox.
- Before saying anything is done, run `sj verify`. Only `verify: ok` means done.
- Skills: sj-explore, sj-propose, sj-clarify, sj-principles, sj-apply, sj-debug, sj-review,
  sj-verify, sj-finish, sj-onboard.
